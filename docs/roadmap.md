# Roadmap

อัปเดตล่าสุด: 2026-11-19

## สถานะปัจจุบัน

โครง Docker, PostgreSQL, Login และ UI shell พร้อมแล้ว โมดูลธุรกิจแรกคือทะเบียนใบสั่งซื้อ (PO) ตามรายงานระบบเดิม พร้อม Login และไทม์ไลน์การแก้ไข กำลังรอ feedback

- [x] UI Workspace ชมพู และ update badge มุมขวาล่างพร้อมเวอร์ชัน

## Phase 0 — ทำความเข้าใจงาน

- [x] บันทึกเป้าหมายเบื้องต้นของระบบ
- [x] ยืนยันการใช้ Docker
- [x] ยืนยันความต้องการ Login และ Audit Trail
- [x] ยืนยันว่าระบบครอบคลุมทั้ง Actual และ Forecast
- [x] ระบุแหล่งข้อมูลเดิมว่าเป็น Excel โดยไม่ใช้ไฟล์จริงในการพัฒนา
- [ ] เก็บและปรับ workflow การทำ Cash Flow จากตัวต้นแบบทีละรอบ (ไม่บล็อกการเริ่มพัฒนา)
- [ ] เก็บรายละเอียด Budget และเงื่อนไขด้านเครดิตทีละรอบ (ไม่บล็อกการเริ่มพัฒนา)
- [x] ยืนยันบทบาท Admin และความสามารถจัดการผู้ใช้/บทบาท/สิทธิ์
- [ ] ระบุบทบาทอื่นและสิทธิ์เพิ่มเติมเมื่อเห็นตัวต้นแบบ
- [ ] ปรับข้อมูลหลักและรายงานจาก feedback เมื่อทดลองใช้งาน

## Phase 1 — วางรากฐาน

- [x] เลือก frontend, backend และ database เบื้องต้น
- [x] สร้างโครง repository และ Docker Compose
- [x] เพิ่ม development command และ auto reload/Compose Watch
- [x] สร้างระบบ config และตัวอย่าง environment variables
- [x] สร้าง database migration แรกสำหรับ Custom User
- [x] สร้าง Authentication และฐาน Authorization ด้วย Groups/Permissions
- [x] แยก Business Admin UI ออกจาก Developer System Admin
- [x] สร้างหน้า Business Admin สำหรับผู้ใช้ บทบาท สิทธิ์ และ reset รหัสผ่าน
- [x] เปิด Django System Admin สำหรับ Developer/Superuser เท่านั้น
- [x] สร้าง Audit Trail กลางและเชื่อมกับการจัดการผู้ใช้/บทบาท
- [x] เพิ่ม automated tests สำหรับ Login, Logout, access control, Business Admin, Audit และ health check
- [ ] ขยาย automated tests เมื่อเพิ่ม Audit Trail และ logic ทางการเงิน

## Phase 2 — ตัวต้นแบบ Cash Flow รุ่นแรก

- [x] สร้างหน้า Dashboard เบื้องต้นด้วยตารางข้อมูลจำลอง: วันที่ รายการ เงินเข้า เงินออก และเงินคงเหลือ
- [ ] สร้างรายการรับ/จ่ายแบบทั่วไปที่รองรับ Actual และ Forecast
- [ ] สร้างหน้ารายการ เพิ่ม แก้ไข และดูประวัติการเปลี่ยนแปลง
- [ ] เปิดให้ผู้ใช้ทดลอง แล้วเก็บ feedback เพื่อปรับข้อมูล หน้าจอ และ workflow

## Phase 2A — ทะเบียนใบสั่งซื้อ (PO)

- [x] ข้อมูลผู้ขาย พร้อมรหัสผู้ขาย เลขผู้เสียภาษี และเครดิตเทอม
- [x] ~~PO แบบมีรายการสินค้า VAT และหัก ณ ที่จ่าย~~ (ทำแล้วพักไว้ ดู DEC-015)
- [x] หน้ากรอก PO ตามคอลัมน์รายงานระบบเดิม และปุ่มบันทึกแล้วกรอกใบต่อไป
- [x] ไทม์ไลน์ประวัติแสดงค่าเดิม → ค่าใหม่ และเหตุผลการแก้ไข
- [x] ยกเลิกพร้อมเหตุผล ไม่มีการลบ
- [x] แสดง PO ที่อนุมัติแล้วและยังไม่ปิดเป็นเงินออกที่คาดว่าจะจ่ายในหน้า Cash Flow
- [x] กันการกรอกปี พ.ศ. ในช่องวันที่
- [x] Automated tests สำหรับสิทธิ์ การแก้ไข audit และหน้าเว็บ
- [x] นำเข้าผู้ขายและเครดิตจาก Excel ของระบบเดิม พร้อมหน้าแสดงตัวอย่างก่อนยืนยัน
- [x] เครดิตไม่ระบุ: ติดป้าย กรองดูได้ และวันครบกำหนดจ่ายเลื่อนตามเมื่อฝ่ายบัญชีกรอก
- [ ] ฝ่ายบัญชีกรอกเครดิตของผู้ขายที่ยังไม่ระบุ
- [ ] ให้ผู้ใช้ทดลองกรอก PO จริงและเก็บ feedback
- [ ] ตัดสินใจทิศทาง: แทนระบบ PO เดิม หรือนำเข้า Excel จากระบบเดิม
- [ ] (ถ้าเลือกนำเข้า) หน้าอัปโหลดรายงาน PO พร้อมตรวจจับการเปลี่ยนแปลงจากรอบก่อน
- [ ] รายการรับ-จ่ายทั่วไปแทน Excel cash flow (รอเห็นรูปแบบไฟล์ที่ใช้อยู่)
- [ ] บันทึกการจ่ายเงินจริงของ PO และย้ายยอดจาก Forecast เป็น Actual

## คำถามสำคัญถัดไป

ประเด็นเหล่านี้ตั้งใจเก็บหลังมีตัวต้นแบบให้ทดลอง และไม่ใช้เป็นเงื่อนไขบล็อกการเริ่มพัฒนา:

1. บทบาทอื่นนอกจาก Admin และสิทธิ์ของแต่ละบทบาท
2. ช่องข้อมูลและ workflow ที่ต่างจากตัวต้นแบบ
3. Budget และเงื่อนไขด้านเครดิต
4. รายงานและมุมมอง Cash Flow ที่ต้องใช้จริง
5. PO: สถานะทั้งหมดของระบบเดิม, ต้องมีขั้นอนุมัติในระบบใหม่หรือไม่ และจะแทนหรือนำเข้าจากระบบเดิม
